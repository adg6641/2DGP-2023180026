# 소닉 애니메이션 뷰어 개발 요구사항

## 1. 목적과 근거

`PRE-PRD.md`를 바탕으로 소닉 스프라이트 시트의 모든 동작을 순서대로 관찰할 수 있는 애니메이션 뷰어를 개발한다. 각 동작을 5회 재생하고 1초 동안 쉰 뒤 다음 동작으로 넘어가며, 전체 동작을 무한 순환한다.

초안에 명시된 조건은 필수 요구사항이다. 초안에서 정하지 않은 창 크기, 확대 배율, 프레임 속도, 휴식 화면과 종료 방법은 이 문서에서 구현 기본값으로 구체화한다.

## 2. 개발 환경 및 산출물

| 항목              | 요구사항                                                                 |
| ----------------- | ------------------------------------------------------------------------ |
| 작업 폴더         | `Labs/LEC09`                                                           |
| 개발 언어         | Python 3                                                                 |
| 그래픽 라이브러리 | pico2d                                                                   |
| 실행 파일         | `sonic_animation_viewer.py`                                            |
| 소스 구성         | 실행 코드와 동작·프레임 데이터 모두 위 Python 파일 하나에 작성          |
| 이미지            | 같은 폴더의 기존`sonic-sprite.png`                                     |
| 창 크기           | 기본 1200 × 800 픽셀 (`WINDOW_WIDTH = 1200`, `WINDOW_HEIGHT = 800`) |
| 확대 배율         | 기본 4배, 모든 동작에 동일 배율 적용                                     |
| 프레임 속도       | 기본 프레임당 0.1초, 동작별 설정 가능                                    |
| 실행 방법         | 저장소 루트에서`python Labs/LEC09/sonic_animation_viewer.py`           |

초안의 `sonic sprite.png`는 실제 파일명인 `sonic-sprite.png`로 정정한다. 이미지 경로는 현재 작업 디렉터리가 아닌 실행 파일의 위치를 기준으로 계산한다. 기존 이미지를 그대로 사용하며 별도 이미지, JSON, 폰트 파일을 필수 실행 자산으로 추가하지 않는다.

## 3. 사용 시나리오

1. 사용자가 프로그램을 실행하면 1200 × 800 픽셀의 창이 열리고 소닉 이미지가 로드된다.
2. 첫 동작의 첫 프레임부터 확대된 애니메이션이 자동 재생된다.
3. 해당 동작의 모든 프레임을 순서대로 표시하는 과정을 정확히 5회 반복한다.
4. 다섯 번째 재생의 마지막 프레임을 1초간 유지한다.
5. 다음 동작의 첫 프레임부터 동일한 과정을 수행한다.
6. 마지막 동작도 5회 재생과 1초 휴식을 마친 뒤 첫 동작으로 돌아간다.
7. 사용자가 ESC를 누르거나 창을 닫으면 프로그램이 종료된다.

## 4. 스프라이트와 동작 정의

### 4.1. 포함 범위와 재생 순서

- 원본 시트에서 소닉이 등장하는 모든 동작과 포즈를 포함한다.
- 제목, 제작자 표기, 장식 및 하단의 다른 캐릭터 이미지는 재생 대상에서 제외한다.
- 기본 순서는 원본 시트의 위쪽 행부터 아래쪽 행까지이며, 각 행 안에서는 왼쪽에서 오른쪽으로 재생한다.
- 이미지의 행은 동작 목록을 작성하는 출발점이다. 실제 동작 경계와 프레임 순서는 이미지 검수 후 확정한다.
- 한 프레임으로 구성된 동작도 동일한 반복·휴식 규칙을 적용한다.

현재 이미지의 육안 확인에 따른 초기 목록은 다음과 같다. 동작명과 크롭 좌표는 구현 초기에 확정하며, 아래 개수는 각 프레임을 확대해 확인한 후 최종 검증에 사용한다.

| ------- | ----------------- | -------------: |
| A01     | 소닉 1행          |             11 |
| A02     | 소닉 2행          |             12 |

프레임 목록을 확정할 때 누락·중복 여부를 확인한다. 실제 검수 결과가 초기 목록과 다르면 근거를 기록하고 이 표를 수정한다. 프레임 수를 맞추기 위해 이미지를 누락하거나 중복 등록하지 않는다.

### 4.2. 프레임 데이터

각 동작은 고유 ID, 이름, 프레임 목록, 프레임 표시 시간을 가진다. 각 프레임에는 크롭 영역 `(x, y, width, height)`와 정렬 기준점을 기록한다.

- 프레임 간격과 크기가 일정하다고 가정하지 않고 개별 크롭 영역을 지정한다.
- 데이터 좌표는 이미지의 왼쪽 위를 원점으로 통일한다.
- pico2d 출력 시 아래쪽 기준 좌표로 변환한다: `bottom = image_height - y - height`.
- 크롭 영역은 이미지 내부에 있어야 하며, 너비와 높이는 양의 정수여야 한다.
- 소닉의 신체, 신발, 잔상 등 해당 프레임의 표현을 포함하고 이웃 프레임이나 문자를 잘라 넣지 않는다.
- 기준점을 사용해 크롭 크기가 달라져도 캐릭터 위치가 불필요하게 흔들리지 않도록 한다. 원본 동작에 포함된 상하 변화는 보존한다.

| FR-02 | 전체 동작 재생 | 확정한 동작 목록의 모든 프레임을 지정 순서대로 표시한다.                                       |

| FR-10 | 오류 안내      | 이미지 누락이나 잘못된 프레임 데이터는 원인을 알 수 있는 메시지로 알리고 종료한다.             |

### 5.1. 재생 상태와 시간 규칙

필수 상태는 `PLAYING`과 `RESTING`이다. 현재 동작 인덱스, 프레임 인덱스, 완료 반복 횟수와 경과 시간을 관리한다.

```text
첫 동작 시작
  → PLAYING: 전체 프레임 5회 재생
  → RESTING: 마지막 프레임 1초 유지
  → 다음 동작 시작
  → 마지막 동작 이후 첫 동작으로 순환
```

- 프레임 수가 N이고 프레임 표시 시간이 d초이면 1회 재생 시간은 `N × d`초이다.
- 동작 하나의 재생·휴식 총시간은 `5 × N × d + 1.0`초이다.
- 마지막 프레임도 d초 동안 표시한 뒤 반복 완료를 판정한다.
- 렌더링이 지연되어 여러 프레임 또는 상태 경계를 넘으면 남은 경과 시간을 다음 프레임·상태로 전달한다. 지연 중 모든 중간 프레임을 실제 화면에 표시할 필요는 없다.
- 1초 휴식을 구현하기 위해 이벤트 처리를 막는 `delay(1.0)`을 사용하지 않는다.
- 기본 속도에서 A01의 1회 재생은 1.1초, 5회 재생은 5.5초, 휴식 포함은 6.5초이다.
- 초기 목록 76프레임·10동작이 확정되고 모두 기본 속도를 사용할 경우 전체 순환 시간은 48.0초이다.

### 5.2. 화면 구성

- 1200 × 800 픽셀의 창에서 캐릭터를 중앙의 관찰 영역에 표시하고 충분한 여백을 둔다. 기본 관찰 중심은 `(600, 400)`이며 프레임별 기준점으로 정렬한다.
- 모든 동작에 같은 확대 배율을 적용한다. 프레임마다 배율을 바꾸어 소닉 크기가 출렁이지 않도록 한다.
- 최대 크기의 프레임과 기준점까지 고려해 1200 × 800 픽셀의 창에서 4배 출력이 잘리지 않는지 확인한다. 잘림이 있으면 먼저 크롭 영역과 표시 기준점을 점검하고 관찰 위치와 여백을 조정한다. 창 크기 또는 공통 배율을 변경해야 한다면 관련 요구사항과 인수 기준을 함께 수정한다.
- 원본 이미지의 투명 영역을 유지하고 소닉 윤곽을 구분하기 쉬운 배경을 사용한다.
- 상태를 검증할 수 있도록 현재 동작 ID, 프레임 번호, 반복 진행 및 재생·휴식 상태를 콘솔 또는 화면 중 한 곳에 표시한다. 콘솔은 상태 전환 중심으로 출력해 매 렌더링마다 로그가 쌓이지 않게 한다.

## 6. 범위와 품질 요구사항

- 이번 버전의 범위는 자동 애니메이션 관찰이다. 이동 경로, 점프 궤적, 게임 조작, 사운드, 동작 선택 메뉴, 일시정지와 배속 조절은 필수 범위에 포함하지 않는다.
- Python 표준 라이브러리와 pico2d만으로 실행한다.
- 이미지 로딩은 반복 루프 밖에서 수행하고, 재생 루프에서는 이벤트 처리·시간 갱신·그리기를 수행한다.
- 동작 데이터, 상태 갱신, 렌더링, 이벤트 처리의 역할을 단일 파일 안에서 함수 또는 클래스로 구분한다.
- 창 크기, 공통 배율, 반복 횟수, 휴식 시간, 기본 프레임 시간을 상수로 관리한다.
- 프로그램 시작과 종료는 `main()` 및 `if __name__ == '__main__':` 구조로 구성한다.
- 문법 검사와 시간 계산 검증에 더해 실제 창에서 모든 동작을 관찰한다. 코드 검증만으로 크롭 품질을 판정하지 않는다.

## 7. 단계별 개발 및 커밋 계획

최소 20단계 이상으로 나누어 개발한다. 아래 24단계는 각각 변경 결과와 확인 기준을 가진 독립적인 작업 단위이며, 각 단계 완료 후 실제 변경을 커밋한다. 여러 단계를 한 번에 구현하고 커밋만 나누거나 빈 커밋으로 횟수를 채우지 않는다.

이 문서 작성 커밋은 아래 구현 단계 수에 포함하지 않는다. 후반 검증에서 발견한 수정은 추가 단계와 커밋으로 기록할 수 있다.

커밋 메시지의 제목과 본문은 한글로 작성한다. 제목은 해당 단계에서 실제로 변경한 내용을 간결하게 설명한다. 파일명, 함수명, 동작 ID 등 코드와 연결되는 기술 식별자는 원래 표기를 유지할 수 있다. 문서 수정과 추가 보정 커밋에도 같은 규칙을 적용한다.

## 8. 검증 및 인수 기준

| ID    | 검증 항목            | 통과 기준                                                                                                                                         |
| ----- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-01 | 파일 구성            | 실행 코드와 프레임 데이터가`sonic_animation_viewer.py` 하나에 있으며 기존 PNG를 사용한다.                                                       |
| AC-02 | 실행 경로            | 저장소 루트와`Labs/LEC09`에서 각각 실행할 수 있다.                                                                                              |
| AC-03 | 이미지 전체 커버리지 | 확정한 전체 목록을 원본과 대조했을 때 소닉 동작·프레임의 누락과 중복이 없다.                                                                     |
| AC-04 | 크롭과 좌표          | 모든 크롭 영역이 이미지 안에 있고, 신체·효과가 잘리거나 이웃 프레임·문자가 섞이지 않는다.                                                       |
| AC-05 | 확대와 정렬          | 1200 × 800 픽셀의 창에서 기본 4배로 표시되며, 화면 잘림과 불필요한 위치 흔들림이 없다. 배율 변경 시 문서에 반영한 공통 배율을 기준으로 검증한다. |
| AC-06 | 정확한 5회 재생      | 모든 동작에서 전체 프레임 5회 재생 후 휴식에 들어가며 6회째 재생을 시작하지 않는다.                                                               |
| AC-07 | 휴식 경계            | 시간 계산 검증에서 정확히 1.0초 휴식하고 실제 실행에서는 다음 화면 갱신 시점에 전환한다. 마지막 프레임과 위치를 유지한다.                         |
| AC-08 | 동작 전환            | 다음 동작은 첫 프레임과 초기 반복 상태로 시작한다.                                                                                                |
| AC-09 | 무한 순환            | 실제 창에서 최소 2회 전체 순환을 관찰하여 마지막 동작 이후 처음으로 돌아오는 것을 확인한다.                                                       |
| AC-10 | 시간 지연            | 여러 프레임·동작 경계를 넘는 경과 시간을 입력해도 잔여 시간이 보존되고 올바른 상태에 도달한다.                                                   |
| AC-11 | 종료                 | 재생 중 및 휴식 중 ESC와 창 닫기가 정상 동작한다.                                                                                                 |
| AC-12 | 오류 처리            | 이미지 누락 및 잘못된 프레임 데이터 발생 시 원인을 안내하고 캔버스를 정리한다.                                                                    |
| AC-13 | 개발 과정            | 최소 20개 구현 단계에 실제 변경·검증·커밋 기록이 있으며 단계별 보고를 확인할 수 있다. 커밋 메시지의 제목과 본문은 한글 작성 규칙을 따른다.      |
| AC-14 | 창 크기              | 기본 캔버스 크기와 창 크기 상수가 각각 가로 1200, 세로 800이며 실제 창에서 확인된다. 크기 변경 시 문서에 반영한 값을 기준으로 검증한다.           |

시간 계산 검증은 반복 완료 직전·직후, 휴식 종료 직전·직후, 마지막 동작에서 첫 동작으로 전환되는 경계를 포함한다. 임시 검증 코드가 필요한 경우 실행 파일에 검증 함수로 두거나 외부 일회성 명령으로 실행하고, 별도 실행 필수 파일을 추가하지 않는다.

## 9. 완료 조건

필수 기능 FR-01~FR-10과 인수 기준 AC-01~AC-14를 모두 충족하면 완료로 판단한다. 최종 보고에는 실행 명령, 확정한 동작·프레임 수, 1200 × 800 창에서의 확대·정렬 확인 결과, 시간 검증과 실제 창 확인 결과, 구현 단계 및 커밋 내역을 포함한다.
