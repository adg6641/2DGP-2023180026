# 소닉 애니메이션 뷰어 개발 요구사항

## 1. 목적과 근거

`PRE-PRD.md`를 바탕으로 소닉 스프라이트 시트의 모든 동작을 순서대로 관찰할 수 있는 애니메이션 뷰어를 개발한다. 이동이 포함된 동작은 프레임 재생과 화면 위치 이동을 동시에 보여 준다. 각 동작을 5회 재생하고 1초 동안 쉰 뒤 다음 동작으로 넘어가며, 전체 동작을 무한 순환한다.

초안에 명시된 조건은 필수 요구사항이다. 초안에서 정하지 않은 창 크기, 확대 배율, 프레임 속도, 휴식 화면과 종료 방법은 이 문서에서 구현 기본값으로 구체화한다.

## 2. 개발 환경 및 산출물

| 항목              | 요구사항                                                                 |
| ----------------- | ------------------------------------------------------------------------ |
| 작업 폴더         | `Labs/LEC09`                                                           |
| 개발 언어         | Python 3                                                                 |
| 그래픽 라이브러리 | pico2d                                                                   |
| 실행 파일         | `sonic_animation_viewer.py`                                            |
| 소스 구성         | 실행 코드와 동작·프레임 데이터 모두 위 Python 파일 하나에 작성          |
| 이미지            | 같은 폴더의 기존`sonic-sprite.png`                                     |
| 창 크기           | 기본 1200 × 800 픽셀 (`WINDOW_WIDTH = 1200`, `WINDOW_HEIGHT = 800`) |
| 확대 배율         | 기본 4배, 모든 동작에 동일 배율 적용                                     |
| 프레임 속도       | 기본 프레임당 0.1초, 동작별 설정 가능                                    |
| 실행 방법         | 저장소 루트에서`python Labs/LEC09/sonic_animation_viewer.py`           |

초안의 `sonic sprite.png`는 실제 파일명인 `sonic-sprite.png`로 정정한다. 이미지 경로는 현재 작업 디렉터리가 아닌 실행 파일의 위치를 기준으로 계산한다. 기존 이미지를 그대로 사용하며 별도 이미지, JSON, 폰트 파일을 필수 실행 자산으로 추가하지 않는다.

화면의 한글 설명은 운영체제에 설치된 한글 글꼴을 사용한다. Windows에서는 맑은 고딕을 우선 사용하며, macOS의 Apple SD Gothic Neo 또는 Linux의 Noto Sans CJK도 지원한다. 프로젝트에 글꼴 파일을 추가하지 않고, 사용할 시스템 글꼴이 없으면 원인을 안내하고 종료한다.

## 3. 사용 시나리오

1. 사용자가 프로그램을 실행하면 1200 × 800 픽셀의 창이 열리고 소닉 이미지가 로드된다.
2. 첫 동작의 첫 프레임이 중앙 기준점 `(600, 400)`에서 시작하고, 이동 동작은 확대된 프레임 재생과 위치 이동이 동시에 진행된다.
3. 해당 동작의 모든 프레임을 순서대로 표시하는 과정을 정확히 5회 반복한다.
4. 다섯 번째 재생의 마지막 프레임·위치·방향을 1초간 유지한다.
5. 다음 동작은 중앙 기준점에서 첫 프레임부터 동일한 과정을 수행한다.
6. 마지막 동작도 5회 재생과 1초 휴식을 마친 뒤 첫 동작으로 돌아간다.
7. 사용자가 ESC를 누르거나 창을 닫으면 프로그램이 종료된다.

## 4. 스프라이트와 동작 정의

### 4.1. 포함 범위와 재생 순서

- 원본 시트에서 소닉이 등장하는 모든 동작과 포즈를 포함한다.
- 제목, 제작자 표기, 장식 및 하단의 다른 캐릭터 이미지는 재생 대상에서 제외한다.
- 기본 순서는 원본 시트의 위쪽 행부터 아래쪽 행까지이며, 각 행 안에서는 왼쪽에서 오른쪽으로 재생한다.
- 이미지의 행은 동작 목록을 작성하는 출발점이다. 실제 동작 경계와 프레임 순서는 이미지 검수 후 확정한다.
- 한 프레임으로 구성된 동작도 동일한 반복·휴식 규칙을 적용한다.

구현 과정에서 원본 이미지와 실제 4배 렌더링 결과를 대조해 확정한 목록은 다음과 같다. 동작명과 개별 크롭 좌표는 `sonic_animation_viewer.py`의 `ANIMATIONS`에 기록되어 있다. 전체 소닉 영역의 불투명 픽셀을 대조한 결과 누락과 중복은 모두 0개이다.

| ------- | ----------------- | -------------: |
| A01     | 소닉 1행          |             11 |
| A02     | 소닉 2행          |             12 |
| A03     | 소닉 3행          |              6 |
| A04     | 소닉 4행          |              9 |
| A05     | 소닉 5행          |              6 |
| A06     | 소닉 6행          |              6 |

### 4.2. 프레임 데이터

각 동작은 고유 ID, 이름, 프레임 목록, 프레임 표시 시간을 가진다. 각 프레임에는 크롭 영역 `(x, y, width, height)`와 정렬 기준점을 기록한다.

- 프레임 간격과 크기가 일정하다고 가정하지 않고 개별 크롭 영역을 지정한다.
- 데이터 좌표는 이미지의 왼쪽 위를 원점으로 통일한다.
- pico2d 출력 시 아래쪽 기준 좌표로 변환한다: `bottom = image_height - y - height`.
- 크롭 영역은 이미지 내부에 있어야 하며, 너비와 높이는 양의 정수여야 한다.
- 소닉의 신체, 신발, 잔상 등 해당 프레임의 표현을 포함하고 이웃 프레임이나 문자를 잘라 넣지 않는다.
- 기준점을 사용해 크롭 크기가 달라져도 캐릭터 위치가 불필요하게 흔들리지 않도록 한다. 원본 동작에 포함된 상하 변화는 보존한다.

### 5.1. 재생 상태와 시간 규칙

필수 상태는 `PLAYING`과 `RESTING`이다. 현재 동작 인덱스, 프레임 인덱스, 완료 반복 횟수와 경과 시간을 관리한다.

```text
첫 동작 시작
  → PLAYING: 전체 프레임 5회 재생
  → RESTING: 마지막 프레임 1초 유지
  → 다음 동작 시작
  → 마지막 동작 이후 첫 동작으로 순환
```

- 프레임 수가 N이고 프레임 표시 시간이 d초이면 1회 재생 시간은 `N × d`초이다.
- 동작 하나의 재생·휴식 총시간은 `5 × N × d + 1.0`초이다.
- 마지막 프레임도 d초 동안 표시한 뒤 반복 완료를 판정한다.
- 렌더링이 지연되어 여러 프레임 또는 상태 경계를 넘으면 남은 경과 시간을 다음 프레임·상태로 전달한다. 지연 중 모든 중간 프레임을 실제 화면에 표시할 필요는 없다.
- 1초 휴식을 구현하기 위해 이벤트 처리를 막는 `delay(1.0)`을 사용하지 않는다.
- 기본 속도에서 A01의 1회 재생은 1.1초, 5회 재생은 5.5초, 휴식 포함은 6.5초이다.
- 확정한 76프레임·10동작이 모두 기본 속도를 사용할 경우 전체 순환 시간은 48.0초이다.

### 5.2. 화면 구성

- 1200 × 800 픽셀의 창에서 각 동작을 중앙 기준점 `(600, 400)`에서 시작한다. 이동 동작은 관찰 영역 안에서 움직이고, 제자리 동작은 중앙에 유지한다. 프레임별 기준점으로 이동 중에도 정렬한다.
- 모든 동작에 같은 확대 배율을 적용한다. 프레임마다 배율을 바꾸어 소닉 크기가 출렁이지 않도록 한다.
- 최대 크기의 프레임과 기준점까지 고려해 1200 × 800 픽셀의 창에서 4배 출력이 잘리지 않는지 확인한다. 잘림이 있으면 먼저 크롭 영역과 표시 기준점을 점검하고 관찰 위치와 여백을 조정한다. 창 크기 또는 공통 배율을 변경해야 한다면 관련 요구사항과 인수 기준을 함께 수정한다.
- 원본 이미지의 투명 영역을 유지하고 pico2d 기본 회색 격자 캔버스를 배경으로 사용한다.
- 동작 설명은 기본 28픽셀 시스템 한글 글꼴로 하단 y=100의 가로 중앙에 표시한다. 글자가 캐릭터와 겹치지 않게 한다.
- 상태를 검증할 수 있도록 현재 동작 ID, 프레임 번호, 반복 진행 및 재생·휴식 상태를 콘솔 또는 화면 중 한 곳에 표시한다. 콘솔은 상태 전환 중심으로 출력해 매 렌더링마다 로그가 쌓이지 않게 한다.

### 5.3. 이동 동작과 경로

이동 속도와 점프 높이는 원본 이미지가 아닌 확대된 창의 픽셀 단위이다. `MOTIONS`에 동작별 이동 데이터를 등록한다.

| ID | 동작 | 수평 속도 | 점프 높이 | 경로 |
| --- | --- | ---: | ---: | --- |
| A01 | 제자리 동작 | 0 | 0 | 중앙에서 자세 변화 |
| A02 | 달리기 | 220픽셀/초 | 0 | 수평 왕복 |
| A03 | 제자리 발차기 | 0 | 0 | 중앙에서 발차기 |
| A04 | 이동 구르기 | 180픽셀/초 | 0 | 수평 왕복 |
| A05 | 구르기 | 180픽셀/초 | 0 | 수평 왕복 |
| A06 | 고속 달리기 | 300픽셀/초 | 0 | 수평 왕복 |
| A07 | 초고속 달리기 | 380픽셀/초 | 0 | 수평 왕복 |
| A08 | 높이 점프 | 130픽셀/초 | 180픽셀 | 수평 왕복과 회차별 포물선 점프 |
| A09 | 방향 전환 달리기 | 200픽셀/초 | 0 | 첫 4프레임은 오른쪽, 다음 4프레임은 왼쪽 |
| A10 | 손들기와 대기 포즈 | 0 | 0 | 중앙 제자리 |

- 프레임 번호와 별개로 동작의 실제 재생 경과 시간에서 위치를 계산한다. 렌더링 빈도가 달라도 같은 재생 시점의 위치·방향은 같다.
- 각 동작 시작 시 위치는 `(600, 400)`이고, 수평 이동은 5회 반복 동안 이어진다. 반복 회차마다 수평 위치를 초기화하지 않는다.
- 캐릭터의 안전 영역은 가로 160~1040, 세로 200~776이며 이동·잘림 검증을 위한 좌표 범위이다. 배경은 기본 캔버스이다. 전체 프레임의 원본 기준점과 좌우 반전 크기, 좌우 여백 24픽셀을 고려한 수평 기준점 범위는 기본 자산에서 264~936이다.
- 경계에서 남은 이동 거리를 버리지 않고 반사한다. 화면 밖으로 순간이동하지 않으며 반사 방향에 따라 소닉을 좌우 반전한다.
- A09는 원본의 방향을 시간에 따라 반영한다. 원본이 왼쪽을 향하는 프레임을 오른쪽 방향 프레임으로 취급하지 않는다. 경계 반사가 없다면 회차 끝에 시작 위치로 돌아온다.
- A08의 한 회차 위상을 u라고 할 때 점프 높이는 `180 × 4 × u × (1 - u)`이다. 매 회차 시작과 끝에는 지면 기준점 y=400으로 돌아온다. 원본 포즈의 기준점 상대 상하 변화는 유지한다. 이전 80픽셀보다 높아진 점프에서도 모든 프레임이 화면 안에 들어와야 한다.
- 5회 재생 완료 시점의 위치·방향을 휴식 내내 유지한다. 다음 동작으로 넘어갈 때 중앙과 원본 첫 프레임 방향으로 초기화한다.
- 창 제목에 현재 위치와 표시 방향을 포함해 이동과 휴식 상태를 관찰할 수 있게 한다.

## 6. 범위와 품질 요구사항

- 이번 버전은 프레임과 화면 위치를 함께 재생하는 자동 애니메이션 뷰어이다. 걷기·달리기·구르기의 이동, 공중 동작의 점프, 경계에서 방향 반전을 구현한다. 게임 조작, 사운드, 동작 선택 메뉴, 일시정지와 배속 조절은 이번 구현 범위에 포함하지 않는다.
- Python 표준 라이브러리와 pico2d만으로 실행한다.
- 이미지 로딩은 반복 루프 밖에서 수행하고, 재생 루프에서는 이벤트 처리·시간 갱신·그리기를 수행한다.
- 동작 데이터, 상태 갱신, 렌더링, 이벤트 처리의 역할을 단일 파일 안에서 함수 또는 클래스로 구분한다.
- 창 크기, 공통 배율, 반복 횟수, 휴식 시간, 기본 프레임 시간, 이동 영역과 동작별 속도·점프 높이를 상수 또는 메타데이터로 관리한다.
- 프로그램 시작과 종료는 `main()` 및 `if __name__ == '__main__':` 구조로 구성한다.
- 문법 검사와 시간 계산 검증에 더해 실제 창에서 모든 동작을 관찰한다. 코드 검증만으로 크롭 품질을 판정하지 않는다.

| AC-19 | 한글 설명 | 10개 동작의 설명이 올바른 한글로 화면 하단 중앙에 표시된다. 동작 전환 시 문구가 바뀌며 캐릭터와 겹치거나 화면 밖으로 나가지 않는다. |
| AC-20 | 기본 배경 | 실제 렌더링이 pico2d 기본 회색 격자 배경을 사용한다. |

시간 계산 검증은 반복 완료 직전·직후, 휴식 종료 직전·직후, 마지막 동작에서 첫 동작으로 전환되는 경계를 포함한다. 임시 검증 코드가 필요한 경우 실행 파일에 검증 함수로 두거나 외부 일회성 명령으로 실행하고, 별도 실행 필수 파일을 추가하지 않는다.

## 10. 구현 결과 및 실행 확인

기본 구현 24단계에 이동 기능 추가 25~27단계, 행별 동작·설명·배경 마무리 28~30단계를 이어서 진행했다. 실행 코드와 동작·이동·설명 데이터는 `sonic_animation_viewer.py` 하나에 있으며 기존 `sonic-sprite.png`와 설치된 시스템 한글 글꼴을 사용한다. 단계별 변경·검증·커밋 해시는 `DEVELOPMENT_REPORT.md`에서 확인할 수 있다.

```powershell
# 자동 재생 시작: ESC 또는 창 닫기로 종료

```
