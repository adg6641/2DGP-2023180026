Drill #8 애니메이션 뷰어 - 기능 구현 설명
학번: 2023180026
소스 위치: 2DGP-2023180026/Labs/LEC08/animation_viewer.py

1. 스프라이트 시트 제작과 애니메이션 종류
제공된 소닉 시트의 프레임 구성과 검사 시트의 캐릭터 스타일을 참고하여,
AI ImageGen으로 어두운 남색 옷과 포니테일을 가진 검사 캐릭터의 스프라이트를 새로 생성했습니다.
최종 생성 원본에서 걷기, 달리기, 점프, 공격의 주요 포즈를 선택하여 투명한 atlas로 만들었습니다.
사용하는 시트는 assets/sprite_atlas.png이고 크기는 1209×798픽셀입니다.
걷기 6프레임, 달리기 8프레임, 점프 7프레임, 공격 5프레임으로 총 26프레임입니다.

2. 정확한 재생, 5회 반복, 1초 정지, 무한 반복
time.perf_counter()로 측정한 실제 경과 시간을 재생 시간에 누적합니다.
프레임 간격은 걷기 0.12초, 달리기 0.085초, 점프 0.13초, 공격 0.12초입니다.
각 동작의 모든 프레임을 순서대로 5번 재생하고 마지막 프레임에서 정확히 1초간 정지합니다.
이후 다음 동작으로 넘어가며, 걷기→달리기→점프→공격 순서를 종료할 때까지 반복합니다.
공격과 1초 정지가 끝나면 다시 걷기의 첫 프레임부터 시작합니다.
동작 전환 때 남은 시간을 다음 동작에 전달하여 렌더링 속도가 달라져도 재생 시간을 유지합니다.
상단에 현재 동작, 재생/정지 상태, 반복 횟수, 현재 프레임 번호를 표시합니다.

3. 화면 중앙 재생과 캐릭터 확대
창 크기는 960×640픽셀이고 캐릭터를 화면 중앙에서 재생합니다.
각 포즈의 가로세로 비율을 유지하면서 표시 높이를 화면 높이의 53%, 약 339픽셀로 확대합니다.
작은 캐릭터가 화면 절반 이상을 차지하도록 했고 모든 포즈의 표시 경계를 검사했습니다.
프레임별 발밑 중심 앵커를 이용하여 프레임 크기가 달라져도 같은 기준 위치에서 재생합니다.
점프 포즈에는 원본의 높이 차이를 적용하되 상단 상태 표시와 겹치지 않도록 제한합니다.

4. 추가점수 항목: 프레임마다 크기가 다른 복잡한 Sprite Sheet 지원
최종 atlas는 동일한 격자 크기로 잘라 사용하는 시트가 아닙니다.
투명 여백을 잘라 실제 그림 크기에 맞게 프레임을 패킹했으므로 각 프레임의 폭과 높이가 다릅니다.
예를 들어 걷기 프레임은 폭 103~111픽셀/높이 171픽셀, 달리기는 폭 124~143픽셀/높이 147~162픽셀,
점프는 폭 96~170픽셀/높이 129~179픽셀, 공격은 폭 109~211픽셀/높이 166~190픽셀입니다.
assets/sprite_atlas.json에 프레임마다 x, y, width, height, pivot_x, pivot_y, offset_y를 저장합니다.
이를 읽어 각기 다른 사각형을 clip_draw()로 그리므로 칼이나 공격 잔상을 포함한 큰 프레임도 지원합니다.
PNG/JSON의 위쪽 기준 y 좌표를 pico2d의 아래쪽 기준 좌표로 변환하여 올바른 영역을 표시합니다.
B 키를 누르면 실제 프레임 경계, 원본 크기, 확대 배율과 발밑 기준점을 화면에서 확인할 수 있습니다.

5. 추가점수 항목: 애니메이션마다 서로 다른 프레임 수 지원
걷기 6개, 달리기 8개, 점프 7개, 공격 5개의 프레임 목록을 각각 독립적으로 관리합니다.
공통된 고정 프레임 수를 사용하지 않고 현재 동작의 len(frames)와 frame_seconds로
현재 프레임과 한 회 재생 시간을 계산합니다. 따라서 프레임 수가 다른 동작도 5회 반복을 정확히 수행합니다.
한 순환의 시간은 걷기 4.60초, 달리기 4.40초, 점프 5.55초, 공격 4.00초로 총 18.55초입니다.
각 시간에는 해당 동작 뒤의 1초 정지가 포함됩니다.

6. 사용자 조작과 실행
SPACE: 수동 일시정지/재개, R: 전체 순서 재시작, B: 프레임 경계 표시, ESC: 종료입니다.
창의 닫기 버튼으로도 종료할 수 있습니다. 수동 정지 중에는 자동 정지의 시간도 멈춥니다.
저장소 최상위 폴더에서 다음과 같이 실행합니다.
python -m pip install -r Labs/LEC08/requirements.txt
python Labs/LEC08/animation_viewer.py
현재 컴퓨터에는 pico2d가 이미 설치되어 있으며 VS Code의 Run Python File로도 실행할 수 있습니다.

7. 개발 과정과 검증
프로젝트 구성, 설정 분리, 데이터 모델, JSON 로딩, 경계 검증, 이미지 로딩, 좌표 변환,
클리핑, 앵커, 확대, 시간 기반 진행, 5회 반복, 1초 정지, 순환 전환, 종료 처리,
일시정지, 재시작, 상태 UI, 진행률, 프레임 경계, 자동 검증, 이미지 적용, 검사와 문서를
기능별로 점진적으로 구현하고 각각 커밋하여 20개 이상의 개발 커밋을 남겼습니다.
커밋 날짜를 소급하거나 빈 커밋을 만들지 않았고 실제 파일 변경으로 개발 단계를 기록했습니다.
자동 검사 8개로 동작 종류/프레임 수, PNG와 JSON 크기, 가변 프레임 경계와 비중첩,
5회 반복/1초 정지, 전체 순환, 작은 시간 간격과 큰 시간 간격의 동등성,
화면 중앙/확대/표시 경계, 좌표 변환, 잘못된 입력 처리를 확인했습니다.
추가로 모든 26포즈와 각 동작의 정지 상태를 실제 pico2d로 렌더링하여 확인했습니다.
